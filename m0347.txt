1. PROJECT TITLE
------------------------------------------------------------------------

ContractLens: An AI-Powered Retrieval-Augmented Generation (RAG) System
for Automated Legal Contract Analysis with Multilingual Support


------------------------------------------------------------------------
2. PROJECT OVERVIEW / ABSTRACT
------------------------------------------------------------------------

ContractLens is an intelligent web-based application that automates the
analysis of legal contracts using Retrieval-Augmented Generation (RAG)
and Large Language Models (LLMs). Users upload contract documents in
PDF, DOCX, or TXT formats and receive:

  - Comprehensive executive summaries (15-section breakdown)
  - Risk identification with severity ratings
  - Key clause extraction and classification
  - Natural language Q&A grounded in retrieved contract clauses
  - Text-to-Speech (TTS) accessibility for audio playback
  - Automatic multilingual support (100+ languages)

The system supports both cloud-based LLMs (Google Gemini) and locally
hosted models (Ollama), with offline fallback mechanisms to ensure
reliability even without internet connectivity.

This project targets the legal-tech domain and aims to reduce legal
review time, increase document accessibility, and lower barriers for
non-English speaking users.


------------------------------------------------------------------------
3. PROBLEM STATEMENT
------------------------------------------------------------------------

Legal contracts are complex, lengthy, and full of technical jargon.
Key challenges include:

  - Non-lawyers struggle to understand contract implications.
  - Manual review is expensive and time-consuming.
  - Non-English contracts are inaccessible to many.
  - Important clauses (liability, termination, IP) are often missed.
  - Accessibility issues for visually impaired users.

ContractLens addresses all these problems using AI automation.

------------------------------------------------------------------------
5. SYSTEM ARCHITECTURE
------------------------------------------------------------------------

The system is built as a Python Flask web application with the
following core components:

  [A] FRONTEND
      - HTML5, CSS3, Vanilla JavaScript
      - Jinja2 templating engine
      - Responsive UI with tabs for different analysis views

  [B] BACKEND (Flask - app.py)
      - User Authentication (OTP-based + Google OAuth)
      - File Upload Handling (up to 16MB)
      - Session & Database Management (SQLite)
      - REST API endpoints for analysis & TTS

  [C] RAG ENGINE (rag.py)
      - Document text extraction (PDF, DOCX, TXT, Scanned PDFs via OCR)
      - Language detection (langdetect)
      - Translation pipeline (Gemini / Ollama / deep-translator fallback)
      - Document chunking (900 chars, 180-char overlap)
      - TF-IDF Vectorization (scikit-learn, character n-grams 3-5)
      - Cosine similarity retrieval
      - LLM-based answer generation (Gemini 2.5 Flash / Ollama)
      - Contract audit & executive summary generation

  [D] DATABASE (SQLite - contractlens.db)
      - users table
      - contracts table
      - otp_codes table

  [E] EXTERNAL SERVICES
      - Google Gemini API (LLM + Translation)
      - Ollama (local LLM fallback)
      - Google TTS (gTTS) for audio output
      - deep-translator (offline translation fallback)
      - Google OAuth 2.0 (SSO authentication)

6. COMPLETE WORKFLOW (Step-by-Step)
------------------------------------------------------------------------

  STEP 1 - DOCUMENT UPLOAD
    User uploads a contract file (PDF / DOCX / TXT).

  STEP 2 - TEXT EXTRACTION
    - PDF: pypdf + PyMuPDF (fitz) for digital PDFs
    - Scanned PDF: Tesseract OCR (pytesseract + Pillow)
    - DOCX: python-docx (preserves table data)
    - TXT: direct UTF-8 read
    - Enhanced error handling for corrupted/empty files

  STEP 3 - LANGUAGE DETECTION
    - Uses langdetect library + Unicode script analysis
    - If English -> skip to RAG pipeline
    - If non-English -> proceed to translation

  STEP 4 - TRANSLATION (if required)
    Primary:  LLM Translation (Gemini or Ollama)
              - High quality, context-aware, legal terminology preserved
    Fallback: Offline Translation (deep-translator / argostranslate)
              - Free, local, no API costs, no internet required
              - 100+ language pairs supported

  STEP 5 - DOCUMENT CHUNKING & INDEXING
    - Smart contract-aware chunking (900 chars, 180 overlap)
    - Section and clause boundary detection
    - TF-IDF vectorization (character n-grams 3-5)

  STEP 6 - AUTOMATED CONTRACT AUDIT
    LLM analyzes the contract and extracts:
    - Metadata (parties, dates, type, jurisdiction)
    - Key clauses (termination, liability, IP, confidentiality, etc.)
    - Risks with severity levels (High / Medium / Low)
    - Missing standard clauses
    - Internal inconsistencies
    - Fallback: local pattern scanning if LLM unavailable

  STEP 7 - EXECUTIVE SUMMARY GENERATION (15-Section Report)
     1. Quick Facts (parties, dates, risk level, agreement type)
     2. What This Agreement Does
     3. Party Obligations (actionable details)
     4. Financial Terms (exact amounts, payment schedules)
     5. Key Dates & Deadlines (start, end, renewal, notice periods)
     6. Termination & Exit (how to exit, penalties)
     7. Liability & Risk (caps, indemnification, insurance)
     8. Confidentiality & Data Handling
     9. Intellectual Property (ownership, licenses)
    10. Restrictions & Prohibitions
    11. Dispute Resolution
    12. Key Risks & Red Flags (color-coded: RED / YELLOW / GREEN)
    13. Action Items (before signing / after signing)
    14. Missing Clauses
    15. Bottom Line Recommendation (Sign / Negotiate / Reject)

  STEP 8 - INTERACTIVE ANALYSIS (4 Tabs)
    Tab 1: Executive Summary (with TTS audio playback)
    Tab 2: Clause Analyzer (all key clauses, severity ratings)
    Tab 3: Risks & Compliance (risk scan, entity extraction, audit)
    Tab 4: Intelligent Q&A (natural language questions, RAG answers
            grounded in contract clauses with citations)

10. AUTHENTICATION SYSTEM
------------------------------------------------------------------------

  A) OTP-Based Passwordless Authentication
     - User enters name + email (registration) or email (login)
     - System generates 6-digit random OTP
     - OTP sent via SMTP email (configurable: Gmail, Outlook, Yahoo)
     - OTP valid for 10 minutes, single-use only
     - On success: account created / user logged in

  B) Google OAuth 2.0 (SSO)
     - Uses Authlib integration
     - Google Cloud OAuth Web Application client
     - Redirect URI: http://127.0.0.1:5000/auth/google/callback
     - Retrieves user profile (name, email)

  Security Features:
     - Time-based expiration (10 min)
     - Single-use OTP (replay attack prevention)
     - Auto-invalidation of old OTPs on new request
     - Email ownership verification

13. ALGORITHMS USED
------------------------------------------------------------------------

  1. TF-IDF Vectorization (Term Frequency - Inverse Document Frequency)
     - Converts contract chunks into numerical vectors
     - Character-level n-grams (3-5 chars) for better recall
     - Handles legal terminology variations

  2. Cosine Similarity
     - Measures similarity between query vector and chunk vectors
     - Retrieves top-k most relevant clauses for each query

  3. Retrieval-Augmented Generation (RAG)
     - Retrieve: TF-IDF cosine similarity on chunks
     - Augment: Retrieved clauses inserted into LLM prompt
     - Generate: LLM produces grounded, citation-backed answers

  4. Language Detection
     - langdetect library (statistical language identification)
     - Unicode script analysis for Indian scripts

  5. OCR Pipeline
     - PyMuPDF renders PDF pages as images (2x resolution)
     - Tesseract OCR (OEM 3, PSM 6) extracts text from images

16. LIMITATIONS AND FUTURE SCOPE
------------------------------------------------------------------------

  CURRENT LIMITATIONS:
  - TF-IDF retrieval may miss semantically similar but lexically
    different clauses (no semantic embeddings yet).
  - LLM-based analysis depends on API availability / rate limits.
  - Uploaded files stored locally (not cloud storage).
  - No admin dashboard or usage analytics.
  - Rate limiting for OTP not yet implemented.

  FUTURE ENHANCEMENTS:
  - Replace TF-IDF with semantic embeddings (sentence-transformers,
    Google text-embedding models) for better retrieval accuracy.
  - Add cloud storage (Google Cloud Storage / AWS S3) for uploads.
  - Implement SMS OTP as alternative authentication channel.
  - Add admin dashboard for monitoring and analytics.
  - Rate limiting on OTP generation to prevent abuse.
  - "Remember this device" option to skip OTP on trusted devices.
  - Export summary as PDF report.
  - Batch contract processing for enterprises.
  - Role-based access control (admin / user / reviewer).

18. SETUP AND DEPLOYMENT INSTRUCTIONS
------------------------------------------------------------------------

  Requirements: Python 3.11+, pip

  STEP 1: Create virtual environment
    python -m venv .venv
    .\.venv\Scripts\Activate.ps1      (Windows PowerShell)
    source .venv/bin/activate         (Linux/macOS)

  STEP 2: Install dependencies
    pip install -r requirements.txt

  STEP 3: Configure environment
    Copy-Item .env.example .env       (Windows)
    cp .env.example .env              (Linux/macOS)
    (Edit .env and fill in API keys, SMTP credentials, etc.)

  STEP 4: (Optional) Install offline translation
    pip install argostranslate
    argospm update
    argospm install translate-hi_en   (Hindi -> English)
    argospm install translate-ta_en   (Tamil -> English)

  STEP 5: Run the application
    python app.py

  ACCESS: http://127.0.0.1:5000
